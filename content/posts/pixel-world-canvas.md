打开这个页面，你看到的天空、远山、亮着窗的城市、走个不停的小人，全部是**代码画出来的**，没有一张图片。

而且它很小 —— 小到只有三四百像素宽。

## 为什么故意把分辨率调低

现代浏览器画布可以轻松跑到 4K，但对像素画来说，分辨率越高越糟糕。想要真正的像素感，必须让**一个逻辑像素吃掉好几个屏幕像素**。

我的做法是：先算出一个"世界宽度"，再按视口比例推出世界高度。

`@js
const vw = innerWidth;
const vh = innerHeight;
this.W = Math.round(clamp(vw / 3.2, 200, 560)); // 每个逻辑像素约 3.2 个 CSS 像素
this.H = Math.round((this.W * vh) / vw);         // 严格保持视口比例，绝不拉伸
this.canvas.width = this.W;
this.canvas.height = this.H;
this.ctx.imageSmoothingEnabled = false;          // 关掉插值，保住硬边
`@

关键是 `canvas.width` 只设为 `W`，然后交给 CSS 把它拉伸到 100vw × 100vh，再配一句：

`@css
canvas { image-rendering: pixelated; }
`@

浏览器就会用**最近邻插值**把 300 像素的画面放大到 1440 像素。放大倍率不是整数也没关系，最近邻只会让像素大小差一个屏幕像素，肉眼几乎看不出来；但如果你用默认的双线性插值，整个画面会糊成一团。

> 这里有个容易踩的坑：不要为了"清晰"去乘 `devicePixelRatio`。那会让你画出来的像素更小、更密，像素感直接消失。

## 九层视差，一层一层叠出来

整个场景拆成九层，每层有自己的滚动系数：

| 层 | 内容 | 滚动系数 |
| --- | --- | --- |
| 1 | 天空渐变 | 0.04 |
| 2 | 星星 / 流星 | 0.05 |
| 3 | 太阳 / 月亮 | 随阅读进度走弧线 |
| 4 | 远云 + 浮空岛 | 0.06 – 0.10 |
| 5 | 远山脊线 | 0.06 |
| 6 | 近山脊线 | 0.11 |
| 7 | 城市天际线 | 0.20 |
| 8 | 树木 + 地面 | 0.34 |
| 9 | 前景剪影 | 0.52 |

远处的层几乎不动，近处的层跑得很快，滚动时就有了一种"世界在往后走"的错觉。

绘制顺序必须**从远到近**，后画的盖住先画的 —— 这一点和 DOM 里的 `z-index` 是一个道理。

## 山脊线其实是一串随机数

远山看起来像精心画的剪影，实际上只是一次带平滑的随机游走：

`@js
const ridge = (base, amp, rough) => {
  const out = [];
  let y = base + (r() - 0.5) * amp * 0.4;
  for (let x = 0; x < W; x++) {
    y += (r() - 0.5) * rough;
    y = clamp(y, base - amp, base + amp * 0.35);
    out.push(Math.round(y));
  }
  // 关键的一步：三点滑动平均，让噪声变成岩石
  return out.map((v, i, a) => Math.round((v + (a[i - 1] ?? v) + (a[i + 1] ?? v)) / 3));
};
`@

没有那次滑动平均，得到的是一排锯齿；有了它，才像山。

随机数用的是一个**带种子的伪随机**（mulberry32），保证每次刷新看到的山一模一样 —— 每次打开都换一座山，会让人怀疑这网站的稳定性。

## 画圆也要一格一格来

`arc()` 画出来的是完美的圆弧，放大后会看到抗锯齿的灰边，和周围硬邦邦的像素格格不入。所以太阳是这么画的：

`@js
for (let dy = -rad; dy <= rad; dy++) {
  const span = Math.floor(Math.sqrt(Math.max(0, rad * rad - dy * dy)));
  this.px(x - span, y + dy, span * 2, 1, body); // 每一行画一条横线
}
`@

一行一条 `fillRect`，得到的圆边缘是阶梯状的，这才是像素画该有的样子。月亮则是把同一个圆**再画一遍**，只是每行往右偏移一点，用天空色盖出一条弯月。

## 让世界自己动起来

静止的像素画只是插画，动起来才是世界。这里的动画全部由**时间**驱动，而不是帧数：

- 星星按 `sin(t * 速度 + 相位)` 呼吸闪烁
- 云按不同速度横向漂移
- 城市窗户各自有随机相位，此亮彼灭
- 每 6 到 18 秒随机来一颗流星
- 小人的走路帧每 150ms 换一次，只有四帧

> 用时间驱动而不是"每帧走一格"，好处是掉帧时动画只会变卡、不会变速。帧率低的时候，世界还是以同样的节奏在呼吸。

至于性能：整块画布大约 300 × 190，每帧发出的 `fillRect` 调用在几百次量级。为了省电，我把它**锁在 30fps**：

`@js
addTick((dt, _t, scrollY) => {
  this.acc += dt;
  if (this.acc < 33) return; // 攒够 33ms 才画一帧
  this.draw(this.acc, scrollY);
  this.acc = 0;
});
`@

30fps 不仅更省电，还意外地更"复古" —— 那种老游戏的顿挫感，恰好是 60fps 给不了的。

## 太阳是可以点的

画布本身设了 `pointer-events: none`，不挡任何交互。但太阳是个例外：每帧我都会把一个透明的 `<button>` 挪到太阳的屏幕位置上，点它就能切换昼夜。

这样既保持了画布的"纯粹"，又白捡了一个彩蛋。
