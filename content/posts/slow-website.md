这是这个站改的第五版。前四版都在追求「看起来厉害」：动效、图层、转场，一样不落。最后都活不过三个月 —— 不是因为坏了，是因为每次想写点什么，都得先跟自己的模板较劲。

## 快和慢不冲突

「打开得快」和「读得慢」是两件事。前者是技术指标，后者是节奏。

所以这一版做了两个看起来矛盾的决定：把首屏压到最小，同时把行距调到 1.9。前者让页面立刻出现，后者让人愿意在页面上停住。

## 三条自己定的规矩

- **没有第三方脚本。** 除了字体文件，页面不向任何外部域名发请求。
- **正文就是 Markdown。** 换台电脑、换个编辑器，文件照样能读，不依赖这个站还活着。
- **先在手机上排版。** 手机上行宽只有三十来个字，能在这里读顺，桌面上就一定不会差。

写页面的时候，模板字符串就够了，不需要任何 UI 框架：

```ts
// 一个视图就是一段 HTML 字符串，插进 DOM 就完事
export function homePage(): View {
  return {
    title: site.seo.title,
    html: '<h1>' + site.name + '</h1><p>' + site.hero.lead + '</p>',
  };
}
```

代价是手写 HTML 容易出错，好处是半年后打开这个文件，我三分钟就能看懂它。

## 慢下来的收益

改完这一版之后，我写东西的次数变多了。

原因说出来有点无聊：因为改一句话不用重启任何东西。写 Markdown、存盘、推上去，一分钟之后线上就是了。工具不再挡在中间，想法才有机会跑到前面。

一个网站最该优化的指标，可能不是首屏时间，而是「从想写到写完」之间的摩擦。
